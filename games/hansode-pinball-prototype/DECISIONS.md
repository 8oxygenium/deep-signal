# DECISIONS（判断の記録）

迷ったときに選んだ方を1行ずつ記録する。

## フェーズ1：準備
- サイトは Cloudflare Pages がリポジトリ直下をビルドなしでそのまま配信する構成（package.json・ビルド設定ファイルが無い）と判断。コミットしたファイルは全部公開される前提で設定した。
- `node_modules/`・`dist/`・`dist-electron/`・`release/`・`*.exe`・テスト出力は、プロトタイプ内とリポジトリ直下の両方の `.gitignore` で除外（二重の保険）。
- ソース置き場 `games/hansode-pinball-prototype/` は `_headers` で noindex、さらに `_redirects` でダウンロードページへ302転送し、Webで「遊べる版」が見えないようにした（Cloudflare Pages の `_redirects` は1パターンにスプラット1つまでなので個別指定）。
- three.js は Vite がバンドルするので devDependencies に置き、インストーラーへ二重に入らないようにした。実行時に必要なのは koffi だけ。
- koffi は Windows x64 用バイナリだけ同梱し、ネイティブ部分は asarUnpack で asar の外に出す（asar 内の .node は読めないため）。
- インストーラーに入れる言語パックは ja / en-US のみ（約45MB削減）。
- 固定キーに加えて「フィルターキー（右Shift 8秒長押し）」「切り替えキー（NumLock 5秒）」のショートカットも同じ手法で無効化する。フリッパーで右Shiftを長押しするとフィルターキーの確認が出てしまうため。
- 固定キー等の変更は fWinIni=0（レジストリに保存しない）で行う。異常終了しても次回ログオンで必ず元に戻り、さらに userData のバックアップから次回起動時にも復元する。
- 固定キー等の無効化は「ウィンドウにフォーカスがある間」だけ。他のアプリに切り替えたらユーザー本来の設定に戻す。
- ユーザーが固定キー機能そのものを ON にして使っている場合は触らない（Microsoft推奨どおり）。
- Windows で左右Shift同時押し中に片方を離すと keyup が届かないことがあるため、メインプロセスで GetAsyncKeyState を4msごとに読む保険を付けた。
- TypeScript は 7.0（ネイティブ版）ではなく安定している 5.9 系を使う。
- `gh`（GitHub CLI）がこのPCに入っていないため、GitHub Releases へのアップロードは `npm run release` で gh があれば自動、無ければ `リリース手順.md` の手順で行う形にした。

## フェーズ2：物理と手触り
- 座標は「ボール直径=1」。遊ぶ範囲 x=-8.6〜8.6（約17.2）＋発射レーンで台幅約19、奥行き約40。
- 重力は実機の転がり加速度（約29）より少し強い 42。ボールの最高速度は 118（1/480秒ステップで1歩 0.25 = 半径の半分）。
- すり抜け対策は「速度上限で1歩を半径未満に」＋「薄い壁とフリッパーは前ステップの位置から反対側へ抜けたら元の側へ戻す」の二段構え。テストで異常速度（900）でも壁とフリッパーは抜けないことを確認。
- フリッパーは無限質量の動く壁として扱い、接触点の回転速度（先端ほど速い）をそのまま伝える。反発係数は速い衝突ほど下がる（デッドフリッパーで勢いを殺してキャッチできるように）。
- フリッパーの上がる速さ：最大30rad/s・加速2600rad/s²で約0.04秒。
- 「台を左から揺らす（Z）」＝左から押す力なのでボールは右へ押される。「/」はその逆、「↑」は奥へ。揺らした方向に画面と台も動く。
- TILT：揺らしの量を内部ゲージで持ち（1回=1、毎秒0.55減る）、2.7を超えるたびに WARNING。2回警告した後にもう一度超えたら TILT。警告はボールごとにリセット。
- 詰まり対策：0.3以内しか動かない状態が5秒続いたら自動で軽く揺らす（TILTには数えない）、7.5秒で安全な位置へ戻す。プランジャー上とフリッパーで抱えている間は対象外。
- 台の外に出たボールも安全な位置へ戻し、回数を記録（テストで0件を確認する）。
- オービットの出口がアウトレーンの真上にならないよう、外壁に「出っ張り」を付けて斜めのシュートにした（発射したボールが毎回アウトレーンに落ちるのを防ぐ）。
- テスト用ウィンドウでは requestAnimationFrame が止まることがあるので、E2E時だけ setInterval でゲームループを回す。

## フェーズ3：ゲームの流れ
- 初回起動時は固定キーの案内画面を先に出す（「次から表示しない」で消せる。設定画面とタイトルからいつでも見られる）。自動無効化が効いているかも画面に表示する。
- タイトルの裏ではデモ（自動でフリッパーを動かすプレイ）を動かし、約28秒ごとに別のステージへ切り替える。デモ中は効果音を鳴らさない（うるさくならないように）。
- ステージ選択では、選んでいるステージの台を3Dでゆっくり回して見せ、そのステージのBGMを流す。
- ランキングはスコア順。IMPOSSIBLE は生存時間も一緒に保存・表示する。名前は英数字3〜8文字（大文字に統一）。
- メニュー操作：キーボードの Esc は「ポーズ」と「戻る」の両方として届くため、メニューでは「戻る」だけを使い、ポーズした直後の「戻る」は無視する（Escで止めて即再開してしまうのを防止）。
- マウスは「実際に動かしたとき」だけフォーカスを移す（画面が出た瞬間にカーソル下のボタンが選ばれて誤操作するのを防止）。
- ウィンドウが非アクティブになったら自動でポーズする。
- ドットマトリクスは 200×44 ドット、5×7 のビットマップ文字を内蔵（外部フォント不要・くっきり）。日本語の説明はその下の帯とサイドパネルに出す。
- E2E（Playwright）は専用の保存先（一時フォルダ）で起動し、本番のユーザーデータを汚さない。

## フェーズ4：MODERN（お手本の台）
- MODERN の流れ：3つのミッション（ドロップ全部→ランプ3回→スピナー30回転）→ CORE スクープでマルチボール（3球）→ ランプでジャックポット（毎回+5万）、2回ごとに CORE でスーパージャックポット。2つ目のミッション達成で一度だけエクストラボール点灯。
- やさしさ：ボールセーブ15秒、左キックバックは毎ボール点灯（右のスタンドアップ2枚でも再点灯）、アウトレーン入口に補助ポスト。
- ランプのUターンは半径1.8以上の円弧にした（急カーブだと手すりに当たって失速し、ほぼ必ず戻ってきたため）。坂の強さ係数も 300→220 に緩めた。
- ドロップターゲットは1枚倒れたらボールが通れる間隔にし、ゆるいアーチ状に並べた（上に乗ったボールが転がり落ちる。平らな棚で止まるのを防止）。
- スタンドアップはオービットの壁に埋め込み（壁との間にV字のくぼみを作らない）。
- 明るい台は床がブルームで真っ白に光るので、テーマごとにブルームのしきい値を指定できるようにした（MODERN は 1.25 で発光部品だけ光る）。
- ステージ担当エージェントが共通部分を触らずに作れるよう、拡張口を先に用意：`Missions`/`LaneSet`、`theme.decorate`（専用3D）、`sfx.custom`（専用効果音）、`kit` に関数（専用BGM編成）、`shapesByTag`、`g.vars`（回転・停電・警報・グリッチ）。
- 残り5ステージは仮ファイルを先に登録し、各担当は自分のファイルだけを編集する（統合時の衝突を避ける）。作り方は STAGE_GUIDE.md。
- 耐久＋到達テスト（tests/stages.test.ts）は全ステージ共通：10分の自動プレイで lost/invalid/例外 0件、10秒以上止まらない、全部の的・ランプに届く。
